# Vehicle models

Generated by `tools/assetgen` (stdlib-only Python, no Blender needed):

```
py tools/assetgen/build.py              # all models
py tools/assetgen/build.py car_sedan    # one model
```

Every model is two files: `<id>.glb` (glTF 2.0 binary, textures embedded) and
`<id>.rig.json` (joints, sockets, lights, wheel data, per-part bounds). The
files are deterministic: same generator code, same bytes. Do not edit them by
hand; change the generator.

| id | what |
|---|---|
| `car_shitbox` | a) worn-out small hatchback |
| `car_sedan` | b) mid-size sedan |
| `car_hyper` | c) mid-engine hypercar |
| `car_f1` | d) open-wheel formula car |
| `tractor` | e) ~200 hp row-crop tractor |
| `trailer_tipper` | f) tandem-axle tipping trailer for the tractor |
| `combine` | g) combine harvester with 9 m header |

## Frames and origin

- The rig file uses the core frame, ISO 8855: x forward, y left, z up,
  metres, radians.
- The `.glb` uses glTF axes: +Y up, +Z forward, +X left, so
  `gltf(x, y, z) = iso(y, z, x)`. It is a proper rotation; Godot imports it
  as is, and the adapter's single ISO-to-Godot basis change applies.
- Origin: on the ground plane, x = 0 midway between the front and rear axle
  (trailer: midway between its two axles), y = 0 on the centreline, model at
  rest ride height with its tyres touching z = 0.

## Nodes and joints

- Every node's rest rotation is identity and its origin is its joint pivot.
  A joint value is an offset from the modelled rest pose: rotate the node by
  `value` about `axis` (revolute/continuous) or translate it by
  `value * axis` (prismatic). The axis is expressed in the parent frame,
  which at rest has the model's orientation.
- The joint is in the node's glTF `extras.joint` (glTF axes; Godot puts
  extras into node metadata) and in the rig file (ISO axes).
- Joint types: `revolute` (min/max rad), `continuous` (wheels, reels,
  augers), `prismatic` (min/max m), `aim` (visual link that closes a
  kinematic loop, e.g. hydraulic rams, lift rods, wishbones: `target_point`
  is a point in the model frame at rest, carried along by node `target`.
  Each frame, rotate the node by the smallest rotation that takes its rest
  direction (pivot -> target_point at rest) onto the current direction; with
  `stretch`, also scale it along that rest direction by current/rest
  distance. `tools/assetgen/viewer.html` has a reference implementation).
- Sign conventions: wheel spin + = rolling forward; steer + = turning left;
  suspension travel + = bump (wheel up); doors, lids, hoods + = opening;
  steering wheel + = steering left.
- Standard names: `susp_XX` (travel) -> `steer_XX` (steered wheels only) ->
  `wheel_XX` (spin), with XX in FL, FR, RL, RR (trailer: 1L, 1R, 2L, 2R).
  `wheel_XX` extras carry `wheel: {radius, width, side}`.
- `bounds_local` in the rig is the axis-aligned box of the node's own mesh in
  its pivot frame at rest: a starting point for collision proxies and aero
  bluff elements (e.g. the combine's unloading auger).

## Sockets

Empty nodes named `socket_*` mark points the sim or the game needs: hitch
points, PTO output, driver eye, exhaust, auger spout, tow eyes. They are
listed under `sockets` in the rig with their parent node, so they move with
their part (e.g. the three-point-linkage hitch balls).

## Lights

Lamp lenses are separate materials with emission off in the file. The rig's
`lights` maps a function (`head`, `tail`, `brake`, `indicator_left`,
`indicator_right`, `reverse`, `beacon`, `work`, ...) to its material names,
the emissive colour and the strength to set when it is on.

## Checking a model

- Browser viewer with a slider per joint:
  `py -m http.server 8765` in the repo root, then open
  `http://localhost:8765/tools/assetgen/viewer.html`.
- Blender (independent importer + preview render):
  `blender -b --factory-startup -P tools/assetgen/blender_check.py -- <id> out.png door_FL=1.0`
  (`VIEW=iso|side|front|rear|top|iso_rear` picks the camera).

All vehicles are generic and class-typical; none reproduces a specific
production vehicle. Dimensions are noted at the top of each generator module.
